# 配置・解放・退避・帰還を単一方策で学ぶ

`outputs/pick_place_ws1`を引き継ぎ、タスクを`place-retreat-return-home-v7`へ拡張する。
従来のモデルは配置後に制御を止める。v7では、その後も同じPPOが手先を動かす。

## 成功条件

1. 把持して持ち上げ、目標へ運び、机に支持させる。
2. グリッパ関節を0.65 rad以上に開く。キューブとの接触がなくなり、目標から22 mm以内で0.4秒静止する。
3. 解放した位置の上で手先を高さ75 mm以上に退避する。横方向のずれは25 mm未満。
4. 待機位置`[0.23, 0.0, 0.09]` mへ戻る。位置誤差12 mm未満、腕の各関節の誤差0.12 rad未満。
5. 指を開いたまま、手先速度0.02 m/s未満、各関節速度0.15 rad/s未満で0.3秒静止する。配置物も静止・支持を維持する。

待機位置へ到達した後は、その時点のモーター指令を保持して静止を確認する。
探索ノイズで静止タイマーが繰り返しリセットされることを避けるためで、
待機位置への移動はすべて方策の出力。保持中に位置条件を外れた場合は方策の制御を再開する。

待機姿勢は固定した上方の姿勢で、ランダムに変わるエピソード開始姿勢とは別。
解放後にキューブへ再接触した場合、または配置物が目標から外れた場合は失敗。
解放前の把持失敗は従来どおり掴み直せる。解放後はREACHへ戻して報酬を得ることはできない。
成功・失敗が確定するまでの期限は、recovery併用時30秒。

## 手元で追加学習する

```bash
uv run python src/task.py train \
  --resume outputs/pick_place_ws1 \
  --output outputs/pick_place_return_home \
  --return-home --recovery \
  --no-cube-relocations --no-domain-randomization --no-disturbances \
  --stage random --fixed-stage --envs 4 --steps 500000 \
  --eval-every 100000 --eval-episodes 5 \
  --learning-rate 0.0001 --target-kl 0.02 \
  --return-start-probability 0.25
```

観測は69→77次元。元の69入力の位置・重み・正規化を保持し、追加8入力の重みを0で開始する。
追加入力は退避・帰還の工程フラグ、静止タイマー、待機位置へのベクトル、解放位置への水平ベクトル。
行動は従来と同じTCP速度xyz＋グリッパ開閉の4次元。
optimizerは構成を変える最初の転移時だけ初期化する。同じ構成からの通常再開では保存済みoptimizerを引き継ぐ。
1つのPPO内で、配置まで・退避・帰還の行動出力を分ける。
既習の接近出力が新工程で飽和して探索できないことを避けるため、退避・帰還の出力は平均0からPPOで学ぶ。
元の配置Actorと観測の正規化は固定し、新工程の独立した小さなネットワークとCriticを更新する。
元の時間入力も24秒基準を保持する。実際の打ち切り期限は30秒で、時間入力は帰還中に1を超えうる。
移動方向や指の開閉の固定動作を教師にしない。
帰還中には目標位置との距離に比例したコストも加え、遠くで待つことを不利にする。

解放後は安全制約として、グリッパを閉じる指令を禁止する。
退避中の関節目標は手先のXY・向きを保つ上向きの成分に射影し、下向きの指令も抑える。
退避中のゼロ指令時は前のモーター目標を保持し、重力補償の予圧を毎回失わないようにする。
帰還中は手先高さ75 mmを下限とする。PPOとACTの両方に同じ制約を適用する。
これは移動先へ自動で運ぶ固定軌道ではなく、実行可能な指令の範囲。上昇・帰還の量は方策が出力する。

訓練では25%のエピソードを退避・帰還から開始し、後半の動作を練習する。
後半だけを先に学ぶウォームアップでは`--return-start-probability 0.75`に増やし、全工程の仕上げで0.25へ戻せる。
その試行は`return_start=true`・`eased_start=true`・`full_task=false`と記録する。
独立検証・watch・ACTデータ収集では途中開始を使わず、全工程を実行する。
したがって訓練ログの成功率は途中開始を含み、全工程の成功率は検証結果で判断する。

再開する場合は`--resume outputs/pick_place_return_home`へ変更する。
`--steps`は追加ステップ数。中断時の保存と、10万ステップごとのチェックポイントがある。
強制終了後は最後の完全な`checkpoints/step_*/`から再開する。

## 学習後にwatchする

```bash
uv run python src/view.py --pick-place evaluate \
  --run outputs/pick_place_return_home/selected \
  --episodes 10 --seed 50000 --watch \
  --recovery --no-cube-relocations --no-domain-randomization --no-disturbances
```

`return_home`は保存設定から復元する。旧モデルをevaluateに渡すだけでは帰還動作は増えない。
`selected`は学習後に検証用シードで選んだチェックポイントをコピーする保存先。

## ColabのACTへ持ち込む

配置から帰還までの方策を評価後にバンドルへ入れる。

```bash
uv run python src/act.py bundle \
  --run outputs/pick_place_return_home/selected \
  --output outputs/act_colab_bundle.zip
```

Colabでは追加PPO学習を行わず、その教師の成功軌跡を収集してACTを学ぶ。
評価時も配置・解放・退避・帰還の条件を引き継ぐ。
以前の配置だけのデータとはDriveの実験名を分ける。

## 実装の検証

閉じた指のままでは配置終了にならないこと、退避と帰還を飛ばせないこと、
静止タイマーのリセット、解放後の再接触が掴み直しへ戻らないことをテストする。
固定動作を使った物理検証では全工程が成功し、同じ6関節指令をACT用インターフェースで再生しても一致する。
旧PPOからの転移直後は、追加入力があっても元の入力に対する出力が変わらないことも確認する。
固定動作は検証専用で、PPOやACTの教師データには使わない。

## 採用した方策と評価

採用先は`outputs/pick_place_return_home/selected`。5,707,400ステップのチェックポイント。
元の`pick_place_ws1`から、この重みに至る経路では597,560ステップ追加学習した。
`outputs/pick_place_return_home_complete`は最後まで学習した保存先で、通常再開に使える。
初期の試行は`outputs/pick_place_return_home/initial_incomplete`に保存した。
`outputs/pick_place_return_home`直下にも採用モデルをコピーしており、最初に案内したwatchコマンドも使える。
再現用には`selected`を指定する。

選択にはシード10000系列を使い、範囲別・推論方法別の成功率の最小値が良い方策を保存した。
採用時のlevel 5・決定論的推論は4/5。他の範囲と固定配置、確率的推論は各5/5。
同率の場合は最初の良いチェックポイントを保持した。

選択後の独立評価はシード62000〜62019、level 5、途中移動・物理ランダム化・外力なし。
**全工程成功は19/20（95%）**。失敗1件はREACH工程でタイムアウトした。
成功例はすべて、十分な開口、解放後の非接触、配置物の静止、待機姿勢で0.3秒静止の条件を再確認した。
採用モデルのviewer確認は、シード50000〜50009で10/10成功した。
少数試行の結果であり、外乱を含む条件の成功率を示すものではない。

結果は`selected/evaluation_holdout.json`、選択条件とコードのハッシュは`selected/selection.json`。
元Actorの重みと元69入力の正規化が完全に一致することを、学習後にも確認した。
回帰テストは50件通過。Colabと同じ依存環境で帰還までの成功軌跡2本の収集と、小さなACTの1更新も確認した。
ACTのGPU本学習はまだ行っていない。
