# Pick and place v5 の設計

## タスクの境界

単一のPPO方策で「近づく → 把持 → 持ち上げ → 運搬 → 机に下ろす → 離す」を学ぶ。
**机に支持された解放を確認した時点で方策の操作を終え、物体の静止を確認して成功にする。**
以後、方策へ次の行動を要求しない。最後のモーター位置指令を保持して物理計算を続ける。
退避の軌跡や解放後の固定動作を実行することもない。物体の速度をゼロにする操作や接着は使わない。
解放時の姿勢・速度が悪く、その後に再接触・落下・位置ずれが起きれば失敗になる。

カメラ画像を入力する方策ではなく、物体・関節などの状態観測による学習。
教師データ、模倣学習、固定動作による事前学習は使用しない。

- `src/task_logic.py`: 計測値と継続時間から段階・成功・失敗を決める状態機械。
- `src/pick_place.py`: MuJoCo、接触計測、手先制御、観測、報酬、初期状態。
- `src/task.py`: PPO、開始状態のカリキュラム、独立検証、保存、viewer。

## 前の設計から改めたこと

解放後も方策が操作し続ける構成では、ランダム試行50回のうち33回が解放確認まで進み、
その後すべて再接触で失敗した。安全な退避まで追加の技能として学ばせていたため、
「一度離したら終わり」という依頼とタスクの境界がずれていた。

v5は支持された解放で操作を終え、終了判定だけ物理計算を続ける。
同じ50シード・ランダム操作の検証では29回が成功し、再接触は4回になった。
これは探索の到達性の確認であり、学習済み方策の成功率ではない。

開発途中のv4の配置20/20は、指が開き切る前の落下を見逃したため無効。
v4.1ではその穴を修正したが、PPOの45万ステップ時点で解放0/20、
SACの比較実験でも解放100,000ステップ時点で0/5だった。
これらの途中モデルは `outputs/experiments/` に分け、v5へ読み込まない。

## 方策と制御器

25Hz、4次元の連続行動。世界座標の手先速度xyz（各軸の指令上限0.08m/s）と
指の開閉速度（目標値の変化上限1.5rad/s）。正で開き、負で閉じる。
一次フィルタ（係数0.5）の後、下向き姿勢を保つ減衰最小二乗Jacobian制御で関節指令へ変換する。
腕の指令増分は1rad/sに制限し、毎回実測姿勢から計算する。
指は位置目標を速度積分し、実測位置±0.06radと開閉範囲に制限する。
把持中に閉じる目標が蓄積し、開く指令の反応が遅れる問題を防ぐ。
指令は2msの物理ステップごとに線形補間して滑らかにつなぐ。

制御器は物体・目標位置やタスクの段階から軌跡を作らない。
どこへ移動し、いつ開閉するかは方策が選ぶ。
手先の指令領域は既定（`workspace_scale=0`）でx=[0.18,0.25]、y=[-0.04,0.115]、z=[0.023,0.09]m。
XYの原点からの距離も0.19〜0.25mに制限する。
`--workspace-scale`を1まで上げると、x=[0.10,0.29]、y=[-0.12,0.18]、半径0.12〜0.29mまで線形に広がる（zは同じ）。
下向き姿勢のままでも把持高さで半径0.10〜0.30mに机と干渉せず届くため、姿勢の制約は変えずに範囲だけ広げる。
recoveryの作業範囲外判定も同じ倍率で広げ、scale=1では指令領域の1cm外側にする。
方策は0.33→0.67→1と段階的に広げて追加学習する。

PPOは128×128のMLP、learning-rate=1e-4、target-kl=0.02、gamma=0.995、
gae-lambda=0.95、entropy係数0.001、探索標準偏差の初期値exp(−0.8)≒0.45。
複数環境から同じ1つの方策へ経験を集める。

## 観測

69次元。関節位置6・速度6・制御目標6、物体位置3・姿勢4・速度6、手先位置3、目標3、
物体と手先の相対位置3、目標と物体の相対位置3、段階one-hot6、継続時間7、
空中解放ラッチ1、把持・支持・ロボット接触3、フィルタ済み行動4、前回行動4、経過時間1。

段階、判定タイマー、フィルタの状態、指の積分目標を観測する。
タイマーは物理ステップごとに秒単位で更新し、方策の操作間隔をまたいで保持する。
解放後の静止確認は最後の1回のstep内で完了するため、その途中で次の行動は要求されない。
経過時間とコストはこの静止確認の物理時間も含む。
`ep_len_mean`は方策の操作回数。終了検査も含む物理時間は`elapsed_seconds`で記録する。

## 成功・失敗条件

3cm・25gの物体、最大16秒。すべての開始段階で配置完了が目標。
両指各0.01N超の法線力を把持、机から物体重量の10%超の支持力を机支持、
ロボットのいずれかの形状から0.01N超をロボット接触とする。

| 段階 | 次への条件 |
| --- | --- |
| REACH | 両指で40ms継続把持 |
| LIFT | 把持した物体中心が高さ65mm以上で60ms |
| TRANSPORT | 高さ55mm以上、目標XYから20mm未満で40ms |
| LOWER | 目標から22mm未満、机支持、並進速度35mm/s未満で60ms |
| RELEASE | 全ロボットとの接触が20ms途切れ、机に支持されている |
| SETTLE | 指令を保持し、下記の条件を400ms連続で満たす |

成功には、机支持、物体中心が目標から22mm未満、並進速度20mm/s未満、
角速度0.5rad/s未満、ロボット接触なしを400ms連続で要求する。
腕を退避させる条件は設けない。方策の操作は既に終了している。

机上2mmの接触許容域より上で全ロボット接触が20ms途切れる、把持を失って落下する、
目標外で解放する、解放確認後に再接触する、作業領域外に出る場合は失敗。
指の開閉角度で接触喪失の判定を遅らせない。
空中解放を始めた後に着地しても、その履歴は消えない。
机の力が微小な跳ね返りで途切れるため、物体中心高さ17mm以下は空中投下に含めない。
ただし解放確定と最終静止には実際の机支持力を必ず要求する。

期限は観測に含むタスクの終了条件で、時間切れも失敗としてterminatedにする。
時間切れの価値を継続タスクとしてbootstrapしない。終了後のstepはエラーにする。

## 報酬

`r = gamma * Phi(next) - Phi(current) + terminal - approach - time - torque - smoothness`

Phiは「段階番号 + 段階内の0〜1の進捗」。接近、持ち上げ高さ、水平運搬、
下ろして机に支持されること、支持された開閉の順に切り替える。
解放後に接近・再把持の項は存在しない。段階達成の追加ボーナスは設けない。
成功+10、失敗−5、時間切れ−15。成功・落下・再接触・時間切れの終了時はPhiを0にする。
時間切れを失敗より重くするのは、期限の罰がgammaで割り引かれる分、
終盤で配置を試みず止まって期限を待つ方が得になるのを防ぐため。
接近中のREACHだけ、把持位置までの距離コスト `0.2/秒 × tanh(距離/0.05m)` を引く。
成功経験が少ない時点でも、物体から離れるより近づく行動を学べるようにする。
把持位置から10mm以上離れている間の閉指にも最大0.05/秒のコストを付ける。
これは報酬で評価する条件で、行動を固定したり閉指を禁止したりする処理ではない。
これらの項は把持以降には存在せず、解放後の再接近も評価しない。
`approach_cost`を別に出力する。
時間コスト0.02/秒、平滑化コスト0.0002×行動差の二乗平均。

トルクコストは0.02×全6軸の上限で正規化した出力トルク二乗平均の時間積分。
最大トルクを16秒続けても約0.32。`torque_cost`、`episode_torque_cost`、`shaping`を分けて出す。
これは銅損の代理指標で、実際の温度・冷却を計算する熱モデルではない。

## 開始状態のカリキュラム

| 開始段階 | 評価時の初期状態 |
| --- | --- |
| release | 机上で物体を実際に把持（中心高さ14.8mm） |
| place | 目標直上、中心高さ27〜40mmで物理把持 |
| transport | 出発位置、中心高さ70mmで物理把持 |
| lift | 出発位置の机上で物体を物理把持 |
| grasp | 出発位置の物体のすぐ上（手先高さ26mm）、指は開いた状態 |
| pick | 机上物体の50mmほど上、指が開いた状態 |
| random | pickに物体XY・目標XY・物体yawの変動を加える |

把持済み初期状態はIKで関節・物体の初期位置を設定し、200msの物理計算と接触で検証する。
weld、接着、教師の運搬・開閉軌跡は使わない。
初期状態が違うだけで、方策と成功条件は共通。

学習では環境の25%を直前の段階に割り当て、忘却を抑える。既定8環境なら現在6・直前2で、方策は共通。
短い試行をエピソード数だけで混ぜると学習サンプルの割合が小さくなるため、環境単位で割り当てる。
1環境の場合は25%の試行を直前の段階から始める。
place・transport・lift・grasp・pickは50%を評価と同じ初期条件、50%を易しい開始にする。
randomは全試行を評価と同じ手先高さ65mm・指の開き0.8radから開始し、位置・向きの変動への学習に集中する。
配置は高さ14.8〜40mm、運搬は目標から出発位置までの線分上に開始を分布させる。
一様乱数の二乗で易しい開始を多く含め、成功経験が途切れないようにつなぐ。
持ち上げは高さ14.8〜70mmを混ぜ、既に学んだ運搬への遷移を含める。
graspは手先を物体のすぐ上に置き、指の開き0.05〜0.8radを混ぜて閉指から学ぶ。
pickは指を0.8radまで開いた状態に統一し、手先高さ27〜65mmを混ぜて接近からつなぐ。`--fixed-stage`でこれらの補助を無効にする。
検証は表の初期条件を使い、`curriculum_start`で学習用の分布と区別する。
`release`・`place`・`transport`・`lift`・`grasp`の成功率を全タスクの成功率に含めない。

50,000ステップごとに独立した環境・固定した正規化統計で、シード10000以降の20試行（変更可能）を
決定的・サンプリング推論で別々に評価する。学習用の乱数状態は保つ。
現在と直前の開始段階の両方で決定的80%以上・サンプリング60%以上の場合だけ進級する。
最終評価はシード20000以降を使う。

## 保存と検証

旧モデルはタスク仕様が異なるため読み込まない。v5は `outputs/pick_place_v5/` を使う。
`policy.zip`、`normalize.pkl`、`config.json` を一緒に保存する。
50,000ステップごとのcheckpoint、各開始段階の検証最良モデルも同じ形式。
再開は段階、累計ステップ、正規化統計、optimizer、成績を読み戻す。
learning-rateとtarget-klの指定は再開時のoptimizerにも適用する。
再開時に`--stage`を指定すると開始段階を上書きできる。指定しなければ保存された段階から再開する。
中断時に複数環境の受信待ちで終了不能にならないことをテストする。

回帰テストは、物理把持・全段階の完遂、空中解放・再接触・連続静止、
解放後に次の行動を要求せずモーター指令が変化しないこと、期限、
学習と評価の開始分布の区別、保存・再開・中断を確認する。
物理検証用の固定動作は学習から独立しており、その成功をRLの成功として報告しない。
試行結果には最大物体高さ、解放時の高さ・机支持・目標距離、最終速度、物理経過時間も記録する。
評価結果のファイル名にはモデルの累計ステップ・シード・試行数・推論方式を含め、異なる評価を上書きしない。

[Reverse Curriculum Generation for RL](https://proceedings.mlr.press/v78/florensa17a.html)。
